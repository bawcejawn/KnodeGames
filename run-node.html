Tools · Run a node

Run your own Koinos node

Start a Koinos mainnet node and block producer on your own computer, step by step. Every step tells you what it does, gives you the exact thing to copy and paste, shows what you should see, and what to do if it doesn't work.

  • ~1 hourof your time, plus waiting
  • 150 GBfree disk space
  • 24/7a computer that stays on
  • $0software; you bring the VHP

Safe by design

  • This page never asks for a private key or recovery words, and never will. If anything does, stop.
  • It never sends your address or anything you type: your address only fills in the commands on your screen. (Like every page here, it counts page views, without cookies.)
  • Your node makes its own key, which stays on your computer. Your KOIN and VHP stay in your own wallet.
  • It uses the official Koinos node, at a version Knode Games has checked, the same way Knode Games runs its own nodes.

Your setup

Pick your computer and type your producer address once. Every command below is written for you. Both are remembered only in this browser.

Your public address only. Never a private key.

0 of 10 steps done

The 10 steps

  1. Check what you need
  2. Install Docker (and Git)
  3. Get the node files, switch on block production
  4. Download, check and unpack the weekly snapshot
  5. Start the node, wait until it's caught up
  6. Register your node's key
  7. Fill your producer wallet with VHP
  8. Keep it live
  9. Check you're producing blocks
  10. Stop, restart, update, back up

How to paste: on Windows, open PowerShell and right-click (or Ctrl+V) to paste, then press Enter. On a Mac or Linux, open Terminal, press ⌘V or Ctrl+Shift+V, then Enter. Run each box once and wait for it to finish before the next.

1

Check what you need

About 10 minutes

What this does: makes sure your computer can run a node all day, every day, before you start.

You need:

  • A computer that stays on 24/7. Windows 10 or 11 (64-bit), a Mac, or Linux. A node only produces blocks while it runs.
  • 4 or more processor cores and 16 GB of memory (8 GB is the bare minimum).
  • About 150 GB free on a fast drive (SSD), on the drive Docker uses (on Windows that's usually C:). The download is about 60 GB and it unpacks to about as much again.
  • A steady internet connection with no data cap: 25 Mbps down and 10 up or better. A cable is better than Wi-Fi.
  • A Koinos wallet (Kondor on a computer or KOIN Vault on a phone) with some KOIN. Its address is your producer address. No wallet yet? Get one here.
  • Time: about an hour of your own work, plus a few hours of waiting while the download runs.

Check your free disk space:

Windows · PowerShell
Get-PSDrive C
Mac · Terminal
df -h /
Linux · Terminal
df -h /

Then stop the computer from going to sleep (a sleeping node misses its blocks):

  • Windows: Start → Settings → System → Power (& battery) → Screen and sleep → set "When plugged in, put my device to sleep after" to Never. Also: Settings → Accounts → Sign-in options → turn on "Use my sign-in info to automatically finish setting up after an update", so your node comes back by itself after Windows updates.
  • Mac: Apple menu → System Settings → Energy (or Battery → Options on a laptop) → turn on "Prevent automatic sleeping when the display is off". Keep a laptop plugged in.
  • Linux: run sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target

You should see: a list of your drives. In the Free column (Windows) or Avail column (Mac/Linux), the number should be 150 GB (shown as 150G) or more.

If it doesn't work
  • Less than 150 GB free? Empty the Recycle Bin / Trash, uninstall programs you don't use, or move big folders (videos, photos) to another drive. On Windows you can also keep Docker's data on another drive: in step 2, Docker Desktop → Settings → Resources → Advanced → Disk image location.
  • Windows says the command isn't found? Make sure you opened PowerShell (Start → type PowerShell → open Windows PowerShell), not the old Command Prompt.
  • Only a laptop? It works, but keep it plugged in, lid open (or set "do nothing" when the lid closes), and on a cable if you can.
2

Install Docker (and Git)

About 30 minutes (plus restarts)

What this does: installs Docker, the free program that runs the Koinos node in neat, separate boxes, and Git, which downloads the official Koinos node files. On Windows it also turns on WSL 2, the part of Windows that Docker runs on.

Windows

  1. Click Start, type PowerShell, right-click Windows PowerShell → Run as administrator → Yes.
  2. Paste the first box below and press Enter. When it says so, restart your computer.
  3. Download Docker Desktop for Windows from docker.com and run the installer. Keep "Use WSL 2 instead of Hyper-V" ticked. Restart when it asks.
  4. Open Docker Desktop. Accept the terms; you can skip signing in. Click the gear (Settings) → General → tick "Start Docker Desktop when you sign in to your computer" → Apply.
  5. Open a normal (not administrator) PowerShell window and paste the second box to install Git. Then close PowerShell and open it again.
  6. Paste the third box to check everything.
Windows · PowerShell (as administrator)
wsl --install
wsl --update
Windows · PowerShell
winget install --id Git.Git -e --source winget
Windows · PowerShell
docker version
docker compose version
git --version
docker run --rm hello-world

Mac

  1. Download Docker Desktop for Mac from docker.com. Pick Apple chip or Intel chip (Apple menu → About This Mac shows which you have). Open it and drag Docker to Applications.
  2. Open Docker from Applications. Accept the terms; you can skip signing in.
  3. Docker → Settings (gear): General → tick "Start Docker Desktop when you sign in". On an Apple chip, also tick "Use Rosetta for x86_64/amd64 emulation on Apple Silicon". Resources → set Memory to at least 8 GB and the disk limit to at least 200 GB (the node's data lives inside it). Apply & restart.
  4. Open Terminal (Applications → Utilities) and paste the box below. If your Mac offers to install the command line developer tools (that's Git), click Install, wait, then paste the box again.
Mac · Terminal
docker version
docker compose version
git --version
docker run --rm hello-world

Linux

  1. Install Docker Engine for your Linux with the official guide: docs.docker.com/engine/install.
  2. Paste the first box: it installs Git, Python and curl, starts Docker with the computer, and lets you use Docker without sudo. Then log out and back in.
  3. Paste the second box to check everything.
Linux · Terminal (Ubuntu / Debian)
sudo apt-get update && sudo apt-get install -y git python3 curl
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
Linux · Terminal
docker version
docker compose version
git --version
docker run --rm hello-world

You should see: version numbers for Docker (with a Server part), Docker Compose and Git, and then the words "Hello from Docker!".

If it doesn't work
  • "docker: command not found" or "cannot connect to the Docker daemon": Docker Desktop isn't open yet. Open it, wait until its whale icon stops moving, then try again.
  • Windows: Docker says WSL needs updating or won't start: in an administrator PowerShell run wsl --update, then wsl --shutdown, and open Docker Desktop again.
  • Windows: "virtualization is not enabled": open Task Manager → Performance → CPU and look at Virtualization. If it says Disabled, turn it on in your computer's BIOS/UEFI settings (search the web for your PC maker + "enable virtualization").
  • Windows: "winget is not recognized": install App Installer from the Microsoft Store, or download Git from git-scm.com and keep every default.
  • Linux: "permission denied" talking to Docker: you haven't logged out and back in since the usermod line. Do that, then try again.

Get the Koinos node files and switch on block production

About 5 minutes

What this does: downloads the official Koinos node setup at a version Knode Games has checked, tells it to produce blocks for your address, and keeps all of the node's data in a Docker volume (a private storage space inside Docker; it's faster and much less likely to get damaged than an ordinary folder).

Type your producer address at the top of the page first. The commands below fill it in for you.

3a. Download the node files

Windows · PowerShell
New-Item -ItemType Directory -Force C:\koinos-node | Out-Null
cd C:\koinos-node
git clone https://github.com/koinos/koinos.git koinos
cd koinos
git -c advice.detachedHead=false checkout b05b8337d0a8d09748f9c2d1faef810ee2f5de28
git rev-parse HEAD
Mac and Linux · Terminal
mkdir -p ~/koinos-node && cd ~/koinos-node
git clone https://github.com/koinos/koinos.git koinos
cd koinos
git -c advice.detachedHead=false checkout b05b8337d0a8d09748f9c2d1faef810ee2f5de28
git rev-parse HEAD

The last line must print exactly b05b8337d0a8d09748f9c2d1faef810ee2f5de28. That proves you have the checked version.

3b. Settings: block production for your address

Windows · PowerShell
cd C:\koinos-node\koinos
New-Item -ItemType Directory -Force config | Out-Null
Copy-Item config-example\* config -Recurse -Force
Copy-Item env.example .env -Force
Add-Content .env "COMPOSE_PROFILES=block_producer,jsonrpc"
(Get-Content config\config.yml -Raw) -replace '(?m)^  # producer:.*$', '  producer: YOUR_PRODUCER_ADDRESS' | Set-Content config\config.yml -NoNewline -Encoding ascii
Select-String -Path config\config.yml -Pattern '^  producer:'
Mac and Linux · Terminal
cd ~/koinos-node/koinos
mkdir -p config && cp -R config-example/. config/
cp env.example .env
echo "COMPOSE_PROFILES=block_producer,jsonrpc" >> .env
sed -i.bak 's|^  # producer:.*$|  producer: YOUR_PRODUCER_ADDRESS|' config/config.yml
grep "^  producer:" config/config.yml

You should see: after 3a, the long code ending ...f5de28. After 3b, one line: producer: 1… with your address. After 3c, koinos-data printed once, then several lines that mention koinos-data.

If it doesn't work
  • 3a says "destination path 'koinos' already exists": you've done 3a before. That's fine: go on to 3b.
  • 3b shows producer: YOUR_PRODUCER_ADDRESS: you copied before typing your address. Type it at the top of the page, copy the 3b box again and run it again (it's safe to repeat).
  • 3b shows nothing: run 3b again (it starts from fresh settings each time). If it still shows nothing, check that you're in the right folder: cd C:\koinos-node\koinos (Windows) or cd ~/koinos-node/koinos.
  • 3c: "yaml" or "mapping" error: the box was only partly pasted. Copy the whole 3c box with its Copy button and run it again; it rewrites the file.
4

Download the weekly chain snapshot, check it, unpack it

Hands-on 10 minutes · waiting 2–8 hours

What this does: saves you days. Instead of replaying the whole chain from block 1, your node starts from Armana's weekly snapshot: a full copy of the chain, made every Sunday at about 04:00 UTC and published about an hour later. The fingerprint (SHA-256) check proves your download is complete and exactly the file Armana published.

4a. Find the newest snapshot

Windows · PowerShell
cd C:\koinos-node
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$i = Invoke-RestMethod https://snapshots.armana.io/index.json
$s = $i.archives | Sort-Object { [int64]$_.height } -Descending | Select-Object -First 1
$old = $null; try { $old = (Get-Content snapshot.json -Raw -ErrorAction Stop | ConvertFrom-Json).name } catch { }
if ((Test-Path snapshot.tar.gz) -and ($old -ne $s.name)) { Remove-Item snapshot.tar.gz; "A newer snapshot is out: the half-finished older download was removed, so 4b starts fresh." }
$s | ConvertTo-Json -Depth 5 | Set-Content snapshot.json
$f = ((curl.exe -sL --ssl-no-revoke $s.sha256_url) -split '\s+')[0]
"Newest snapshot: $($s.name)"
"Size: {0:N1} GB" -f ($s.size_bytes / 1GB)
"Fingerprint: $($s.sha256)"
if ($f -eq $s.sha256) { "The list and its fingerprint file agree (both from Armana)" } else { "STOP: Armana's list and fingerprint file differ - do not use this snapshot" }
Mac and Linux · Terminal
cd ~/koinos-node
python3 - <<'EOF'
import json, os, urllib.request
i = json.load(urllib.request.urlopen("https://snapshots.armana.io/index.json"))
s = max(i["archives"], key=lambda a: int(a["height"]))
try:
    old = json.load(open("snapshot.json"))["name"]
except Exception:
    old = None
if os.path.exists("snapshot.tar.gz") and old != s["name"]:
    os.remove("snapshot.tar.gz")
    print("A newer snapshot is out: the half-finished older download was removed, so 4b starts fresh.")
json.dump(s, open("snapshot.json", "w"), indent=1)
f = urllib.request.urlopen(s["sha256_url"]).read().decode().split()[0]
print("Newest snapshot:", s["name"])
print("Size: %.1f GB" % (s["size_bytes"] / 2**30))
print("Fingerprint:", s["sha256"])
print("The list and its fingerprint file agree (both from Armana)" if f.lower() == s["sha256"].lower() else "STOP: Armana's list and fingerprint file differ - do not use this snapshot")
EOF

Extra careful (recommended): both fingerprints above come from Armana. To check against a second source, compare the Fingerprint line with the one Armana posts in the Koinos community (Discord or Telegram) or with another node runner's. If they differ, don't use the snapshot.

4b. Download it (the long part)

Leave this window open until it finishes. If it stops for any reason, paste the same box again: it carries on where it left off.

Windows · PowerShell
cd C:\koinos-node
$s = Get-Content snapshot.json -Raw | ConvertFrom-Json
curl.exe -L --fail --ssl-no-revoke --retry 10 -C - -o snapshot.tar.gz $s.url
Mac and Linux · Terminal
cd ~/koinos-node
URL=$(python3 -c 'import json;print(json.load(open("snapshot.json"))["url"])')
curl -L --fail --retry 10 -C - -o snapshot.tar.gz "$URL"

4c. Check the fingerprint

Windows · PowerShell
cd C:\koinos-node
$s = $null
if (Test-Path snapshot.json) { $s = Get-Content snapshot.json -Raw | ConvertFrom-Json }
if (-not $s -or $s.sha256 -notmatch '^[0-9a-fA-F]{64}$') { "STOP - no snapshot.json yet: do 4a first" }
elseif (-not (Test-Path snapshot.tar.gz)) { "STOP - no snapshot.tar.gz yet: do 4b first" }
elseif ((Get-FileHash snapshot.tar.gz -Algorithm SHA256).Hash -eq $s.sha256) { "MATCH - the download is complete and unchanged" }
else { "NO MATCH - delete snapshot.tar.gz and download again" }
Mac and Linux · Terminal
cd ~/koinos-node
EXP=$(python3 -c 'import json;print(json.load(open("snapshot.json"))["sha256"].lower())' 2>/dev/null)
if [ ${#EXP} -ne 64 ]; then echo "STOP - no snapshot.json yet: do 4a first"
elif [ ! -f snapshot.tar.gz ]; then echo "STOP - no snapshot.tar.gz yet: do 4b first"
else
  GOT=$( (sha256sum snapshot.tar.gz 2>/dev/null || shasum -a 256 snapshot.tar.gz) | cut -d' ' -f1)
  if [ "$EXP" = "$GOT" ]; then echo "MATCH - the download is complete and unchanged"; else echo "NO MATCH - delete snapshot.tar.gz and download again"; fi
fi

4d. Unpack it into the node's volume

This unpacks only the two parts a block producer needs (chain and block_store). It never touches your node's key.

Windows · PowerShell
docker run --rm -v koinos-data:/k -v C:/koinos-node:/dl:ro debian:bookworm-slim sh -c "set -e; if [ -e /k/chain ] || [ -e /k/block_store ]; then echo STOP: this volume already holds chain data. See If it does not work.; exit 1; fi; rm -rf /k/restore; mkdir /k/restore; tar -xzf /dl/snapshot.tar.gz -C /k/restore --wildcards '*.koinos/chain/*' '*.koinos/block_store/*'; if find /k/restore -type l -o -type b -o -type c -o -type p | grep -q .; then rm -rf /k/restore; echo STOP: the snapshot holds unexpected links. Do not use it.; exit 1; fi; mv /k/restore/.koinos/chain /k/chain; mv /k/restore/.koinos/block_store /k/block_store; rm -rf /k/restore; echo UNPACKED OK; ls /k"
Mac and Linux · Terminal
docker run --rm -v koinos-data:/k -v "$HOME/koinos-node:/dl:ro" debian:bookworm-slim sh -c "set -e; if [ -e /k/chain ] || [ -e /k/block_store ]; then echo STOP: this volume already holds chain data. See If it does not work.; exit 1; fi; rm -rf /k/restore; mkdir /k/restore; tar -xzf /dl/snapshot.tar.gz -C /k/restore --wildcards '*.koinos/chain/*' '*.koinos/block_store/*'; if find /k/restore -type l -o -type b -o -type c -o -type p | grep -q .; then rm -rf /k/restore; echo STOP: the snapshot holds unexpected links. Do not use it.; exit 1; fi; mv /k/restore/.koinos/chain /k/chain; mv /k/restore/.koinos/block_store /k/block_store; rm -rf /k/restore; echo UNPACKED OK; ls /k"

You should see: 4a: the newest snapshot's name (like koinos-mainnet-2026-11-01-h40694989.tar.gz), its size (about 58 GB) and "The list and its fingerprint file agree (both from Armana)". 4b: a progress line that counts up to 100%. 4c: MATCH (it takes several minutes to answer). 4d: after 30–60 minutes, UNPACKED OK and the words block_store and chain.

If it doesn't work
  • 4a says STOP: don't use that snapshot. (On older Windows 10, "Could not create SSL/TLS secure channel" means Windows needs its updates; the box already asks for the modern connection type.) Wait an hour and try again; if it keeps happening, ask in the Koinos community.
  • 4b stops or the computer restarts: paste the 4b box again. It continues where it stopped. A new snapshot appearing meanwhile doesn't matter: Armana keeps each one listed for about two weeks. If it ever stops with "404", that snapshot was retired: do 4a again (it clears the old half-download), then 4b.
  • 4c says NO MATCH: delete the file (Windows: Remove-Item C:\koinos-node\snapshot.tar.gz; Mac/Linux: rm ~/koinos-node/snapshot.tar.gz), then do 4a, 4b and 4c again.
  • 4d says "No space left on device": if you're repairing a node (step 8), delete the old data first, it's damaged anyway: docker run --rm -v koinos-data:/k alpine:3.20 rm -rf /k/chain-old /k/block_store-old. Otherwise free up disk space (Windows: Docker Desktop → Settings → Resources; Mac: raise Docker's disk limit to 200 GB), then run 4d again. It cleans up its half-done work first.
  • 4d says "STOP: this volume already holds chain data": if you saw UNPACKED OK before, it's done: go on to step 5. If you never saw it (for example you started the node before 4d), do the repair box in step 8, then 4d again, or the node rebuilds the chain from block 1, which takes days. (If you're repairing a node, follow "Repair from a fresh snapshot" in step 8.)
  • Why trust Armana? Armana runs koinos.armana.io, the Koinos API Knode Games itself uses. Their list and fingerprint file both come from Armana, so the check proves the download is intact and is the file they published. It can't contain a key: you only unpack the chain data, and your node makes its own key when it starts. If you'd rather not use a snapshot at all, skip 4b–4d: the node then rebuilds the whole chain itself, which takes much longer.
5

Start the node and wait until it's caught up

A few minutes · catching up: a few hours

What this does: starts your node. It reads the snapshot, then fetches the blocks made since Sunday from other nodes until it's level with the network.

5a. Start

Windows · PowerShell
cd C:\koinos-node\koinos
docker compose up -d
Remove-Item C:\koinos-node\heal-paused -ErrorAction SilentlyContinue
Mac and Linux · Terminal
cd ~/koinos-node/koinos
docker compose up -d
rm -f ~/koinos-node/heal-paused

5b. Is it caught up?

Run this now, then again every 15 minutes or so. Your node is caught up when Behind by is under 10.

Windows · PowerShell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$me = $null; $net = $null
$body = '{"jsonrpc":"2.0","id":1,"method":"chain.get_head_info","params":{}}'
try { $me = [int64](Invoke-RestMethod http://127.0.0.1:8080 -Method Post -ContentType application/json -Body $body).result.head_topology.height } catch { }
try { $net = [int64](Invoke-RestMethod https://koinos.armana.io -Method Post -ContentType application/json -Body $body).result.head_topology.height } catch { }
if (-not ($me -gt 0)) { "Your node didn't answer yet - wait 2 minutes and try again" }
elseif (-not ($net -gt 0)) { "Couldn't read the network height - try again in a minute" }
else { "Your node: $me   Network: $net   Behind by: $($net - $me) blocks" }
Mac and Linux · Terminal
B='{"jsonrpc":"2.0","id":1,"method":"chain.get_head_info","params":{}}'
H='import json,sys;h=int(json.load(sys.stdin)["result"]["head_topology"]["height"]);assert h>0;print(h)'
ME=$(curl -s -X POST -H 'content-type: application/json' -d "$B" http://127.0.0.1:8080 | python3 -c "$H" 2>/dev/null)
NET=$(curl -s -X POST -H 'content-type: application/json' -d "$B" https://koinos.armana.io | python3 -c "$H" 2>/dev/null)
if [ -z "$ME" ]; then echo "Your node didn't answer yet - wait 2 minutes and try again"
elif [ -z "$NET" ]; then echo "Couldn't read the network height - try again in a minute"
elif [ "$NET" -lt "$ME" ]; then echo "Couldn't read the network height - try again in a minute"
else echo "Your node: $ME   Network: $NET   Behind by: $((NET - ME)) blocks"; fi

Want to watch it work? docker compose logs --tail 20 chain (in the koinos folder) shows the latest progress lines.

You should see: 5a: the first time, Docker downloads the node's programs (a few minutes), then lines ending in Started for amqp, chain, mempool, block_store, p2p, block_producer and jsonrpc. 5b: Behind by getting smaller each time you run it. A snapshot can be up to a week old (about 200,000 blocks), so catching up can take a few hours.

If it doesn't work
  • 5b: "Unable to connect" or "Connection refused": the node is still starting. Wait 2 minutes and try again.
  • Behind by stays the same (or grows) across two checks 15 minutes apart: your node is stuck. Restart it: docker compose down then docker compose up -d (in the koinos folder), and check again in 15 minutes.
  • 5a: "port is already allocated" (8080 or 8888): another program uses that port. Pick free ones: add JSONRPC_PORT=8090 and/or P2P_PORT=8898 on new lines at the end of the .env file in the koinos folder, run 5a again, and use 8090 instead of 8080 in 5b. An update (step 10) rewrites .env, so add those lines again after updating.
  • 5a: "external volume koinos-data not found": run docker volume create koinos-data, then do step 4d again before starting.
  • Mac: "platform (linux/amd64) does not match": turn on the Rosetta setting from step 2, restart Docker, and run 5a again.
6

Register your node's key for your address

About 5 minutes

What this does: tells Koinos: "blocks signed by this node count for my address, using my VHP". Your node made its own key pair when it first started. You register only the public half, from your wallet. The private half never leaves the node, and you never need to see it.

6a. Show your node's PUBLIC key

Windows · PowerShell
docker run --rm -v koinos-data:/k:ro alpine:3.20 cat /k/block_producer/public.key
Mac and Linux · Terminal
docker run --rm -v koinos-data:/k:ro alpine:3.20 cat /k/block_producer/public.key

6b. Register it

  1. Open Register a producer key.
  2. Click Connect wallet and connect the wallet whose address you put in step 3.
  3. Paste the public key from 6a into Node PUBLIC key and click Register key.
  4. Confirm in your wallet. This uses a little of your wallet's Mana (check your Mana).

You should see: 6a: one line of about 44 letters and numbers starting with A. That's your public key: safe to share. 6b: "Done. The key becomes active in about a minute."

If it doesn't work
  • 6a: "No such file": the node hasn't made its key yet. Make sure step 5a ran, wait 2 minutes, try again.
  • Anything asks you for a private key or recovery words: stop. Never type or paste those anywhere. Registering needs only the public key and your wallet's own confirmation.
  • The producer page shows a different address than step 3: switch to the right account in your wallet. The key must be registered by the same address the node produces for.
  • "Not enough Mana": wait a while (Mana refills over time) or add a little KOIN to the wallet, then try again.
7

Fill your producer wallet with VHP

About 10 minutes

What this does: gives your node its weight. On Koinos, the more VHP (Virtual Hash Power) your producer address holds, the more blocks it gets to produce. You make VHP by burning KOIN, 1 for 1.

  • How much? Any amount produces some blocks; more VHP means more blocks. We suggest starting with about 10,000 VHP. See what to expect for any amount on Producer lookup.
  • Keep some KOIN unburned. The Koinos docs warn against burning all of it: your wallet needs some KOIN, and the Mana that comes with it, to keep working. We suggest keeping about 100 KOIN.
  • Get KOIN: Get KOIN and VHP (vKOIN and the Vortex bridge).
  • Burn KOIN into VHP: Burn KOIN, with the same wallet as your producer address.
  • Want KOIN back later? Swap VHP → KOIN in one step.
  • New VHP starts counting for production about a minute (20 blocks) after it arrives.

You should see: your wallet showing the VHP. On Producer lookup your address appears once it produces its first blocks (step 9).

If it doesn't work
  • Burned with the wrong wallet? VHP counts for the address that holds it. Burn again with the producer wallet, or send the VHP to it.
  • Not sure how much to burn? Start smaller; you can always burn more later. Burning can't be undone except by swapping VHP back on the Swap page.
8

Keep it live

1 minute a week

What this does: keeps your node producing week after week, and shows you how to fix the two problems node runners meet most: a stuck node and a damaged one. These are the same fixes Knode Games uses on its own nodes.

Already done for you

  • Crashes fix themselves: every part of the node is set to restart automatically if it stops.
  • Restarts fix themselves: Docker starts when you sign in (step 2) and starts your node with it.
  • Safer storage: your node's data sits in a Docker volume (step 3), not an ordinary folder. A folder shared between Windows and Docker is slow for a database and the most likely cause of damaged node data.

Turn on automatic self-heal (recommended)

A small script checks your node every 20 minutes, using the same rules Knode Games uses for its own nodes. If the node has frozen (far behind and not moving, or not answering), it restarts it: at most once every 50 minutes and 3 times in 6 hours, then it stops and tells you. If the node keeps crashing, it doesn't restart it (that can't fix damaged data); it tells you to repair it (below). It never deletes anything, never touches your key, and only asks your node and a public Koinos node for their height. It tells you with a notification and writes a log (heal.log in your koinos-node folder).

First download it and check its fingerprint:

Windows · PowerShell
cd C:\koinos-node
Invoke-WebRequest https://raw.githubusercontent.com/bawcejawn/KnodeGames/main/node/one/heal-one-node.ps1 -OutFile heal-one-node.ps1 -UseBasicParsing
if ((Get-FileHash heal-one-node.ps1).Hash -eq "2888638cfa73a41a626015c41d419d2febca4297d84db690ef9181d3c2094d53") { "MATCH - the file arrived intact" } else { "NO MATCH - don't run it; delete heal-one-node.ps1" }
Mac and Linux · Terminal
cd ~/koinos-node
curl -fsSL -o heal-one-node.py https://raw.githubusercontent.com/bawcejawn/KnodeGames/main/node/one/heal-one-node.py
GOT=$( (sha256sum heal-one-node.py 2>/dev/null || shasum -a 256 heal-one-node.py) | cut -d' ' -f1)
[ "$GOT" = "76c8c5091c09f14ceb840854c25eebec76fd09fe407878a73ffa1145ddf4ec97" ] && echo "MATCH - the file arrived intact" || echo "NO MATCH - don't run it; delete heal-one-node.py"

If it says MATCH, the file arrived exactly as published on Knode Games' GitHub. Try it once (it changes nothing), then switch it on:

Windows · PowerShell
powershell -ExecutionPolicy Bypass -File C:\koinos-node\heal-one-node.ps1 -DryRun
powershell -ExecutionPolicy Bypass -File C:\koinos-node\heal-one-node.ps1 -Install
Mac and Linux · Terminal
cd ~/koinos-node
python3 heal-one-node.py --dry-run
python3 heal-one-node.py --install

You should see a line like OK: height …, network … from the try, then "OK … is set up". It never starts a node you stopped yourself (it reminds you every few hours instead), and the repair, stop and update boxes on this page pause it while they work. On Windows it shows a notification when it acts; on a Mac or Linux a notification may not appear, so look at heal.log in your koinos-node folder. To switch it off, run the same file with -Uninstall (Windows) or --uninstall (Mac/Linux). To update it when this page shows a new fingerprint, do the two boxes above again. Moved your node to another port in step 5? Add -Rpc http://127.0.0.1:8090 (Windows) or --rpc=http://127.0.0.1:8090 (Mac/Linux) to both lines.

Once a week (1 minute)

  • Run the check from step 5b: Behind by should be under 10.
  • Look up your address on Producer lookup (it works from your phone too): you should see recent blocks.

If it's stuck: restart it

Stuck means Behind by is large and doesn't shrink across two checks 15 minutes apart.

Windows · PowerShell
cd C:\koinos-node\koinos
docker compose down
docker compose up -d
Mac and Linux · Terminal
cd ~/koinos-node/koinos
docker compose down
docker compose up -d

If it keeps crashing: repair from a fresh snapshot

Damaged means it keeps restarting or freezing again soon after every restart: docker compose ps shows Restarting, or docker compose logs --tail 40 block_store shows panic. A restart won't cure that; fresh chain data will. This keeps your node's key, sets the old data aside (not deleted) and clears the old download. Short of space? A repair briefly needs room for the old data, a new download and a new unpack (about 180 GB). If your drive is smaller, delete the old data right after this box with the last box below: it's damaged anyway.

Windows · PowerShell
New-Item -Force C:\koinos-node\heal-paused | Out-Null
cd C:\koinos-node\koinos
docker compose down
docker run --rm -v koinos-data:/k alpine:3.20 sh -c "set -e; rm -rf /k/chain-old /k/block_store-old; mv /k/chain /k/chain-old; mv /k/block_store /k/block_store-old; echo MOVED ASIDE; ls /k"
cd C:\koinos-node
Remove-Item snapshot.tar.gz, snapshot.json -ErrorAction SilentlyContinue
Mac and Linux · Terminal
touch ~/koinos-node/heal-paused
cd ~/koinos-node/koinos
docker compose down
docker run --rm -v koinos-data:/k alpine:3.20 sh -c "set -e; rm -rf /k/chain-old /k/block_store-old; mv /k/chain /k/chain-old; mv /k/block_store /k/block_store-old; echo MOVED ASIDE; ls /k"
cd ~/koinos-node
rm -f snapshot.tar.gz snapshot.json

Then do step 4 again (4a to 4d) and step 5. You don't need to register again. Once it's run well for a day, delete the old data:

Windows · PowerShell
docker run --rm -v koinos-data:/k alpine:3.20 rm -rf /k/chain-old /k/block_store-old
Mac and Linux · Terminal
docker run --rm -v koinos-data:/k alpine:3.20 rm -rf /k/chain-old /k/block_store-old

You should see: after a restart, all parts Started again and Behind by shrinking within 15 minutes. After a repair, MOVED ASIDE, then steps 4 and 5 as the first time.

If it doesn't work
  • Disk getting full? Once your node has caught up, delete the download: Windows Remove-Item C:\koinos-node\snapshot.tar.gz, Mac/Linux rm ~/koinos-node/snapshot.tar.gz. You can also remove old Docker programs: docker image prune.
  • Never run docker volume prune, docker system prune --volumes or docker volume rm koinos-data unless you mean to delete your node: they erase its data and its key.
  • The repair box says "can't rename" or "No such file": there was nothing to move (the data was already gone). Go straight to step 4.
  • Self-heal says NO MATCH: don't run it. Delete the file, wait a few minutes and download it again; if it still doesn't match, the page or the file is being updated, so try again later.
  • Mac: a box asks if Terminal may "administer your computer" when you switch on self-heal: click OK. That lets it add its 20-minute timer.
  • Still stuck after a repair: check your internet connection and that the PC's date and time are correct (Settings → Time & language → Set time automatically).

Check you're producing blocks

A few minutes, then a few hours of waiting

What this does: confirms everything is connected: synced node, registered key, VHP in the producer wallet.

  1. Open Producer lookup and enter your producer address.
  2. It shows the blocks your address has signed and what to expect for your amount of VHP. With less VHP, blocks come less often: give it a few hours.
  3. For a closer look, see what your block producer is doing:
Windows · PowerShell
cd C:\koinos-node\koinos
docker compose logs --tail 30 block_producer
Mac and Linux · Terminal
cd ~/koinos-node/koinos
docker compose logs --tail 30 block_producer

You should see: your address with recent blocks on Producer lookup. Block rewards arrive in your producer wallet as KOIN.

If it doesn't work
  • No blocks after a day? Check, in order: step 5b says caught up; step 3b shows your address; you registered the key from 6a with that same address (registering again is fine); the VHP is in that same address.
  • You moved the node to a new computer? The new node has a new key: register it (step 6). Never run the same key on two computers at once.
10

Stop, restart, update and back up

As needed

What this does: covers everyday care: stopping safely, updating to new Koinos versions, and an optional offline backup of your node's key.

Stop and start safely

Windows · PowerShell
cd C:\koinos-node\koinos
New-Item -Force C:\koinos-node\heal-paused | Out-Null; docker compose down      # stop (self-heal pauses)
docker compose up -d; Remove-Item C:\koinos-node\heal-paused -ErrorAction SilentlyContinue     # start again
Mac and Linux · Terminal
cd ~/koinos-node/koinos
touch ~/koinos-node/heal-paused; docker compose down      # stop (self-heal pauses)
docker compose up -d; rm -f ~/koinos-node/heal-paused     # start again

Restarting the computer is fine too: the node comes back by itself when Docker starts.

Update to a new Koinos version

When a new Koinos node version is announced, Knode Games checks it and updates the version code in step 3a on this page. To update: stop the node, fetch the new files, run 3b again (it rebuilds the settings from the new version, with your address), then start:

Windows · PowerShell
New-Item -Force C:\koinos-node\heal-paused | Out-Null
cd C:\koinos-node\koinos
docker compose down
git fetch origin
git -c advice.detachedHead=false checkout b05b8337d0a8d09748f9c2d1faef810ee2f5de28
git rev-parse HEAD
Mac and Linux · Terminal
touch ~/koinos-node/heal-paused
cd ~/koinos-node/koinos
docker compose down
git fetch origin
git -c advice.detachedHead=false checkout b05b8337d0a8d09748f9c2d1faef810ee2f5de28
git rev-parse HEAD

Then step 3b, then step 5a. Your data, key and the volume setting (3c) stay as they are.

Back up your node's key (optional)

Your node's private key is the file block_producer/private.key inside its volume. It controls nothing but signing blocks for your address; your KOIN and VHP stay safe in your wallet. You don't have to back it up: on a new computer you can simply register the new node's key (step 6). If you'd like a copy anyway, put it straight onto a USB stick, then keep the stick somewhere safe and offline. Plug in the stick first and use its drive letter or name:

Windows · PowerShell (USB stick is E:)
if (Test-Path E:\) { docker run --rm -v koinos-data:/k:ro -v E:/:/usb alpine:3.20 cp /k/block_producer/private.key /usb/koinos-node-private.key; if (Test-Path E:\koinos-node-private.key) { "Saved on E:" } } else { "STOP - there is no drive E: Plug in the USB stick and use its letter" }
Mac · Terminal (USB stick named MYUSB)
if [ -d /Volumes/MYUSB ] && diskutil info /Volumes/MYUSB >/dev/null 2>&1; then docker run --rm -v koinos-data:/k:ro -v /Volumes/MYUSB:/usb alpine:3.20 cp /k/block_producer/private.key /usb/koinos-node-private.key && ls /Volumes/MYUSB/koinos-node-private.key; else echo "STOP - no USB stick named MYUSB: plug it in and use its name"; fi
Linux · Terminal (USB stick named MYUSB)
if mountpoint -q "/media/$USER/MYUSB" 2>/dev/null; then docker run --rm -v koinos-data:/k:ro -v "/media/$USER/MYUSB:/usb" alpine:3.20 cp /k/block_producer/private.key /usb/koinos-node-private.key && ls "/media/$USER/MYUSB/koinos-node-private.key"; else echo "STOP - no USB stick named MYUSB: plug it in and use its name"; fi
  • Never open it, paste it, email it, upload it or type it into any website or chat, including this one.
  • Never run the same key on two computers at the same time.

You should see: a stop or start finishing within a minute; after an update, the new version code from git rev-parse HEAD; after a backup, a file named koinos-node-private.key on your USB stick.

If it doesn't work
  • Your USB stick isn't E:? Open File Explorer → This PC to see its letter, and change E:/ in the box. On a Mac, the name under Locations in Finder replaces MYUSB (on Linux, the name in your file manager). If it says STOP, the stick isn't where the box looks: nothing was copied.
  • Want to remove the node completely? Switch self-heal off first (-Uninstall / --uninstall, step 8), then docker compose down, then docker volume rm koinos-data (this deletes its data and key), then delete the koinos-node folder. Your VHP and KOIN stay in your wallet.
